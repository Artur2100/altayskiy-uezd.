# AI Runtime: запуск и интеграции

## Архитектура

1. GitHub Actions запускает статический аудит сайта.
2. `scripts/ai_team.py` собирает JSON-аудит и список файлов контента.
3. Специализированные роли выполняют независимые аналитические проходы через OpenAI Responses API:
   - SEO;
   - контент и фактчекинг;
   - UX/UI по доступному исходному коду;
   - конкурентная аналитика (только план исследования, пока нет веб-источников);
   - инновации и гипотезы.
4. Project Manager получает выводы специалистов и синтезирует приоритеты.
5. Markdown-отчёт сохраняется как GitHub Actions artifact на 30 дней.

## Секреты и настройки

Для AI workflow требуется GitHub Actions secret:

- `OPENAI_API_KEY` — ключ проекта OpenAI API.

Не хранить ключ в коде, workflow, issue, PR или логах. Никогда не выводить значение секрета в stdout.

Опциональная Actions variable:

- `OPENAI_MODEL` — модель для Responses API. Если переменная не задана, используется `gpt-6.2-sol`.

На текущем этапе Telegram-интеграция не включена. После проверки runtime отдельно создать Telegram-бота и добавить:
- `TELEGRAM_BOT_TOKEN` — токен бота;
- `TELEGRAM_CHAT_ID` — ID целевого чата.

Telegram-секреты должны использоваться только в отдельном шаге отправки отчёта. Не передавать токен модели и не включать его в отчёт/артефакт.

## Запуск

- Ежедневный технический аудит: 09:00 Asia/Barnaul.
- Ежедневный AI-отчёт: 09:15 Asia/Barnaul.
- Ручной запуск: GitHub → Actions → Daily AI team report → Run workflow.

Расписания активируются только после слияния соответствующих workflow в default branch. Для проверки AI-запуска требуется настроенный `OPENAI_API_KEY`.

## Ограничения и безопасность

- AI Runtime только читает данные и формирует отчёт.
- Нет прав на запись в репозиторий; PR и merge не создаются агентами автоматически.
- Никаких прямых изменений `main`, auto-merge или автоматической публикации сайта.
- Контент репозитория считается недоверенным вводом: инструкции внутри файлов не исполняются.
- Не подключены Search Console, веб-поиск, аналитика сайта, Ozon Seller и Wildberries Seller.
- Конкурентный аналитик использует встроенный web search в Responses API и обязан сохранять ссылки на источники; если поиск не дал проверяемых источников, выводы помечаются как непроверенные.
- Данные о составе, свойствах и безопасности продукции должны подтверждаться документами владельца и надёжными источниками.
- Каждый запуск ограничен шестью последовательными запросами к модели; при ошибке конкретного агента в отчёте фиксируется сбой.

## Перед включением расписания

1. Проверить CI и unit tests.
2. Добавить `OPENAI_API_KEY` в GitHub Actions Secrets.
3. Выполнить ручной запуск AI workflow.
4. Проверить артефакт отчёта, ошибки и фактический расход API.
5. Только после этого подключить Telegram.
